The blocking chain decides who even reaches a gate. Rules live in ordered rulesets; the first match wins.

MODEL

  • Conditions match on IP/CIDR, user-agent, ASN, ISP, country, or city (geo uses stored intel; unknown intel never matches).
  • Logic: all / any / not / xor; conditions can be negated individually.
  • Actions: block shows the decoy, allow stops the chain and lets the request through. Block can auto-ban.

TOOLS

  • Presets are seeded disabled; enable selectively. The dry-run page tests an IP+UA against the whole chain before you ship a rule.
  • Import/export as JSON for versioning; import_ip_feed pulls remote vendor/scanner feeds into a set.

EDGE DEFENSE

Blocking rules

Rulesets are evaluated top to bottom; the first matching rule wins. An ALLOW rule stops the chain, so place allow rules (trusted operators) before block rules to override them. Drag rows to reorder; drag set headers to reorder sets.
